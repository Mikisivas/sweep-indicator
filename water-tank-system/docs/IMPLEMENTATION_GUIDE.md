# Implementation Guide — Smart Water Tank Monitoring & Control System (IFT 211)

This is a complete, copy-and-reproduce guide for the whole project. It explains
**how the system was designed and built step by step**, gives the **exact
commands to rebuild and re-verify it from scratch**, and embeds the **full
contents of every file** so you can recreate the folder by copy-paste alone.

The project is an individual submission built with **pure digital logic**
(gates + D flip-flops only — no microcontrollers, no abstract blocks) and
delivered as a **Logisim `.circ`** circuit that opens in both Logisim Evolution
and classic Logisim 2.7.1.

## Part B — The design, step by step

### Step 0 — Understand the inputs (thermometer coding)

Four probes: **S0** (Empty, bottom), **S1** (25 %), **S2** (50 %), **S3** (Full,
top). A probe reads 1 when water covers it, so a physically valid reading is
*thermometer-coded* — if a higher probe is wet, all lower probes are wet:

| Water | S3 S2 S1 S0 | Level | L1 L0 |
|-------|-------------|-------|-------|
| dry | 0 0 0 0 | Empty | 0 0 |
| <25 %| 0 0 0 1 | Empty | 0 0 |
| 25 % | 0 0 1 1 | 25 % | 0 1 |
| 50 % | 0 1 1 1 | 50 % | 1 0 |
| 100 %| 1 1 1 1 | Full | 1 1 |

The other 11 codes are impossible → treated as **don't-cares** in the K-maps.

### Step 1 — Sensor encoding (combinational)

Fill a 4-variable truth table for L1, L0 with don't-cares, then K-map:

- **L1 = S2** (one 8-cell group, S2 = 1).
- **L0 = S1·S̄2 + S3** (groups `S1·S̄2` and `S3`).

S0 drops out of the minimized logic entirely (it only ever indicates "still
Empty"), so it is wired to an indicator LED and its redundancy is stated
explicitly. Gates used: 1 NOT, 1 AND, 1 OR.

### Step 2 — Comparator (full detection)

Detecting `LEVEL = 11` is a 2-bit equality against all-ones → a single AND:
**FULL = L1 · L0**.

### Step 3 — Pump control

Pump runs below full, stops at full → **PUMP = NOT(FULL) = NAND(L1, L0)**. One
gate. Purely combinational, so the pump stops the instant FULL appears (no clock
needed).

### Step 4 — Level register (memory)

Two positive-edge **D flip-flops** capture the level on each CLOCK rising edge
(`R1 ← L1`, `R0 ← L0`) and hold it between edges, giving a stable value for the
display. Both flip-flops' asynchronous clear inputs are driven by RESET.

### Step 5 — Overflow counter + alarm

A 2-bit **synchronous** counter (`Q1 Q0`) advances only while FULL = 1 and
**saturates at 3** so the alarm stays on while the risk persists. Next-state
K-maps over (FULL, Q1, Q0):

- **D1 = FULL·(Q1 + Q0)**
- **D0 = FULL·(Q1 + Q̄0)**   (Q̄0 taken from the flip-flop's complement output)

Alarm fires at count 3: **ALARM = Q1 · Q0**. FULL = 0 forces the count back to
00 on the next edge; RESET clears it asynchronously.

### Step 6 — 7-segment decoder

The registered level `R1 R0` (BCD 0–3) drives a gate-built decoder (active-high
segments a–g):

| Seg | Expression |
|-----|------------|
| a | R1 + R̄0 |
| b | 1 |
| c | R̄1 + R0 |
| d | = a (R1 + R̄0) |
| e | R̄0 |
| f | NOR(R1, R0) |
| g | R1 |

Only two shared inverters (R̄1, R̄0) are needed. These seven signals drive the
7-segment display component and are also brought out on pins `SEG_A…SEG_G` for
testing.

Full derivations, truth tables, and K-maps are in `docs/REPORT.md`.

## Part C — How the circuit file was actually produced

The `.circ` file is plain XML, but hand-placing 134 components with pixel-exact
wire coordinates is error-prone. The reproducible method used here:

1. **Probe the real component geometry.** Logisim's own jar was used as a
   library to print the exact port offsets of every gate, pin, flip-flop and the
   7-segment display (e.g. a size-30 AND gate has inputs at (-30, ±10) relative
   to its output; a D flip-flop has CLK at (-40, 0), D at (-40, 20), Q at (0, 0),
   complement Q̄ at (0, 20), and async set/clear on its south edge).
2. **Generate the XML from a Python script** (`gen_circuit.py`) that places each
   component at a known anchor and derives every wire endpoint from those
   verified offsets. Nets are joined with **named tunnels** instead of long
   wires, which keeps routing trivially correct.
3. **Self-check before emitting.** The generator asserts that no wire dangles,
   no wire endpoint lands mid-segment of another wire, and no two nets overlap —
   catching wiring bugs at generation time.

## Part D — How it was verified (this is what makes it trustworthy)

The circuit is not just *claimed* to work; it was simulated headlessly through
the **real Logisim engine** and checked against an independent model:

1. `TableDriver.java` loads the actual `.circ`, sets the input pins for each test
   vector, propagates the circuit to a stable state, and prints every output pin.
2. `verify.py` contains a from-scratch **reference model** of the intended
   behaviour, generates the test vectors (an exhaustive sweep of all 16 sensor
   codes **plus** a full operational scenario), runs them through `TableDriver`,
   and compares every output bit.
3. Result: **71 steps, 0 mismatches**, logged to `verification_log.md`.

Scenarios covered: every level 0→3, pump ON→OFF and OFF→ON, the exact
3-clock-cycle alarm, counter saturation, asynchronous RESET (including RESET
while FULL), and all invalid/non-thermometer sensor patterns.

## Part E — Reproduce everything from scratch

```bash
# 0. Prerequisites: Java (JDK) and Python 3.
# 1. Get the Logisim engine (also the app you open the circuit in):
curl -L -o logisim.jar \
  "https://downloads.sourceforge.net/project/circuit/2.7.x/2.7.1/logisim-generic-2.7.1.jar"

# 2. (Re)generate the circuit from the script:
python3 gen_circuit.py water_tank.circ
#   -> "wrote water_tank.circ: 134 components, 95 wires - all sanity checks passed"

# 3. Build the headless test-bench and run the full verification:
javac -cp logisim.jar TableDriver.java
python3 verify.py water_tank.circ
#   -> "71 steps, 0 mismatches" and regenerates verification_log.md

# 4. Open the circuit interactively:
java -jar logisim.jar water_tank.circ     # or open it in Logisim Evolution
```

**Driving it by hand in Logisim:** pick the **Poke** tool (hand icon), click the
`S0…S3` pins to set a thermometer code (50 % ⇒ S0=S1=S2=1), and click `CLOCK`
0→1→0 for one cycle. Watch the 7-segment digit, the `PUMP_ON` LED, and — after
three clock cycles at full — the `ALARM_LED`. Poke `RESET` to clear.
